## A 认领协议（租约）

### A.1 核心主张（一句话）

> **在文件形态下，认领不是「去改卡」，而是「原子地独占创建一个专属路径」。**

卡本体（`card.md`）**任何 agent 都不许改**（F5：一个路径一个写者）。agent 对卡的全部动作，都表达为**往自己独占的文件里写**；卡的真相由这些文件**重放**得出。因此：

- 「谁持有这张卡」＝ `lease/active/` 下**存不存在**一个未释放的租约目录；
- 「两个 agent 同时抢」＝ 两个进程同时尝试**创建同一个路径**，文件系统保证只有一个成功。

排他性**不来自**「先读后写」的检查，也不来自「加个锁标志位再写」——前者有 TOCTOU 竞态，后者有「文件已存在但内容还没写完」的空窗。**排他性只来自创建动作本身**：目标已存在 ⇒ 创建失败。

### A.2 为什么是「原子创建目录名」，而不是「锁文件 + 内容」

| 做法 | 竞态窗口 | 本席判定 |
|---|---|---|
| 读 `lease.json` → 若空则写 | 两个进程都读到「空」，都去写 | `不可用`（TOCTOU） |
| 创建 `lock` 文件，再写持有者进去 | 创建成功后、内容写一半被杀 ⇒ 后来者读到空文件，误判「没人持有」 | `部分可用`（需额外「空即占用」规则，易错） |
| **原子创建目录，把身份编码进目录名** | **无窗口**：目录名由系统调用一次性落地，名字里已含持有者/取道时刻/随机数 | **`可用`（本件采纳）** |

**做法**：租约＝一个**目录**，目录名即租约身份，形如

```
lease/active/L__<席号>__<engine>__<epoch_ms>__<nonce>/
```

创建用「存在即失败」的原子创建（POSIX：`mkdir`／`open(O_CREAT|O_EXCL)`；Windows/NTFS：`CreateDirectory`／`CreateFile(CREATE_NEW)`）。两个进程同时打，**恰好一个成功**，另一个收到「已存在」——它**不是**「我以为我拿到了」，而是**系统明确告知**「你没拿到」。

目录内再放 `owner.json`（字段见 A.4）。即使内容写入未完成就被杀，**目录存在**这件事已足够表示「占用中」——后来者一律按「占用」处理，⛔ 不按「空即空闲」处理。

> **适用范围（诚实边界）**：该原语在**本地 NTFS / 本地 POSIX 文件系统**上可靠；在部分网络共享（SMB／老 NFS）上历史上不可靠。⇒ 硬约束：看板数据目录⛔ 放在网络盘／云同步盘（OneDrive／Dropbox 之类），必须是**本机磁盘**上的普通目录。这一条要写进 `ENVIRONMENT.md`（本席未实测，列为**待实测项**）。

### A.3 数据布局（每张卡一个目录）

```
board/
  cards/
    <card-id>/
      card.md                     # 卡意图：目标/领地/交付物/验收判据（建卡人一次写，之后只读）
      events/                     # append-only 事件流：一次状态迁移＝一个新文件
        000001__created__<actor>__<nonce>.json
        000002__claim__<actor>__<nonce>.json
        000003__heartbeat__<actor>__<nonce>.json   # 心跳也可以是文件（见 A.5）
        000004__submit__<actor>__<nonce>.json
      lease/
        active/                   # 原子创建；正常占用时恰有 1 个（0 或 1 合法，>1 即破）
          L__<席号>__<engine>__<epoch_ms>__<nonce>/
            owner.json
            hb/                   # 心跳证据：每个心跳一个新文件（不覆写）
              hb__<epoch_ms>__<nonce>.json
        released/                 # 正常释放：目录被原子 rename 进来，附 release.json
        reclaimed/                # 超时回收：目录被原子 rename 进来，附 reclaim.json
      artifacts/                  # 产物区（每个席位写自己的文件）
        <artifact-name>__<席号>__<口径>.<ext>
      evidence/                   # 凭据件（见 §C）
        <evidence-id>__<席号>.json
  _index/                         # 派生快照（Web 看板读它）；可弃可重建，⛔ 不是真相源
```

**关键点**：
- `events/` 与 `lease/` 下的条目**只增不改**（append-only）；更正＝新增一条并引用被更正项。
- **没有任何两个 agent 写同一个文件**：事件/心跳/租约都以「席号＋时刻＋随机数」命名。
- 释放与回收＝**原子 `rename`**（原子且目标存在即失败）：`active/L__…/` → `released/L__…/` 或 → `reclaimed/L__…/`。rename 成功后，`active/` 里就少了一个。

### A.4 租约字段表（`owner.json`）

| 字段 | 类型 | 必填 | 谁写 | 为什么需要 / 不填出什么事 |
|---|---|---|---|---|
| `lease_id` | string（＝目录名） | 是 | 持有者（创建时） | 租约唯一身份；缺则释放/回收无法点名 |
| `owner_seat` | string（席号，如 `工兵D2`） | 是 | 持有者 | 追责主体；缺则回收后说不清「原来是谁」 |
| `engine` | enum（hermes/codex/qoderclicn/opencode/other） | 是 | 持有者 | 引擎不同判据不同（§B.2）；也用于度量台账 |
| `model` | string | 是 | 持有者 | 防「坏模型静默回落」（P3 行 21）；缺则假绿无法归因 |
| `session_id` | string | 是 | 持有者 | 断点续跑的钥匙（§3 行 26）；缺则失联后只能重派、上下文归零 |
| `acquired_at` | 双读：`date`＋`epoch_ms` | 是 | 持有者 | 算 TTL；⛔ 单读不够（时刻字段可能被写死，§3 行 28） |
| `expires_at` | epoch_ms | 是 | 持有者 | ＝取得时刻＋TTL；机器可判「是否过期」 |
| `ttl_s` | int | 是 | 持有者（取板级默认） | 每次可声明，但⛔ 不得超板级上限；缺则无过期语义 |
| `heartbeat_interval_s` | int | 是 | 持有者 | 回收判据的分母；缺则无法判「心跳该多久来一次」 |
| `heartbeat_seq` | int（单调递增） | 是 | 持有者 | 判「心跳是否在推进」；只增不减，回退即异常 |
| `renew_count` / `max_renew` | int / int | 是 | 持有者 | 续约次数上限，防「无限续约赖着不走」 |
| `attempt_nonce` | string（随机） | 是 | 持有者 | 防同名目录误判；也是事件去重键 |
| `card_rev_at_claim` | string（事件流末尾的 rev 指纹） | 是 | 持有者 | 认领时卡处于哪一版；若卡被改过，回收/续跑能察觉 |
| `prev_lease_ref` | string（上一条租约 id 或 null） | 是 | 持有者 | 续租/重夺时串起历史链；缺则看不出「第几次抢」 |
| `progress_ref` | string（最后一次进度标记路径） | 否 | 持有者 | 回收时定位「原进度在哪」；⛔ 仅作下界（§3 行 27） |

**设计决策**：`已定`（字段集＝上表）。**待拍板**：`ttl_s` 与 `heartbeat_interval_s` 的**具体默认值**（见 A.5）。

### A.5 心跳与超时判定

**判定只用盘上读数，⛔ 不用自报时刻。** 心跳＝`hb/hb__<epoch_ms>__<nonce>.json` 一次次新建文件（⛔ 不覆写同一个心跳文件——覆写既违「一文件一写者」，又让「刚才那次心跳」无法回读）。

超时判据（三读数，取最严）：

1. **mtime 读数（主判据）**：`now - max(mtime of hb/*)` > TTL ⇒ 判超时。mtime 由文件系统给，agent 改不了。
2. **文件内自报 epoch（参考）**：与 mtime 差 > 容差（建议 120s）⇒ 报警「时刻不可信」，但**不单独据此回收**。
3. **心跳序号停滞**：`heartbeat_seq` 连续两个窗口未增 ⇒ 即使 mtime 新（可能是有人碰文件）也报警。

**TTL 取值依据**：

- 既有正档的 **120s** 是**引擎道租约**的数（§6 行 47），它服务「进程还在不在」——可用 `tasklist` 证（进程活着就是 0/1 的硬事实）。
- 看板卡租约的对象是**agent 会话**，一次 LLM 往返＋落盘通常是**分钟级**；套用 120s 会把「正常思考中的 agent」误回收。
- 因此本件建议：**心跳间隔 60s，TTL 600s（10 分钟），即容忍连续 10 个心跳窗口静默**。
- 为什么是「10×」而不是「2×」：心跳是**意愿证明**（agent 愿意写就写），不是**活着证明**；单次工具调用可能卡在长命令上。宁可回收晚一点（回收是可逆的：持有者回来仍能进 verify，见 A.6），也不要误杀正在干活的席。
- ⛔ 该阈值**必须落档 + 可配**，改动走「改闸门前先留档旧件」（全局规则 17）。

**状态标签**：`active`（心跳新鲜）／`stale`（超过 1 个窗口未见心跳，黄）／`expired`（超 TTL，红，可回收）。**退化必须可见**（`AGENTS.md` §1 硬纪律 3）：`stale` 要在看板上变色，⛔ 静默。

### A.6 回收流程

**谁有权回收**：**发牌席**（或发牌席书面指定的「回收席」，一次一事）。⛔ 执行者不得回收自己的租约（会掩盖自己的失联）；⛔ 被回收者不得自行把 `reclaimed/` 改名回去。

**回收四步（每步都可机器判）**：

1. **验超时**：读 A.5 三条读数，全指向 `expired`。任一读数不支持 ⇒ 不回收，报警。
2. **认领回收权**：回收者同样用**原子创建**抢 `lease/reclaim.lock`（存在即失败）。这样**两个回收者同时动手也只有一个成功**——回收本身也是竞争，也要排他。
3. **原子改名**：`active/L__…/` → `reclaimed/L__…/`（rename；目标已存在即失败 ⇒ 再证一次幂等）。
4. **写回收件** `reclaimed/L__…/reclaim.json`（字段见下）。

**回收留痕字段**（红线 3 明令「谁回收、什么时刻、原执行者是谁」）：

| 字段 | 内容 |
|---|---|
| `original_lease_id` / `original_owner_seat` / `original_session_id` | 原持有者是谁、原会话是什么（续跑钥匙） |
| `reclaimer_seat` / `reclaimed_at`（双读） | 回收者与回收时刻 |
| `reason` | 哪条读数超阈（`hb_mtime_age=…s > ttl=…s` 之类，⛔ 不写「感觉卡了」） |
| `last_hb_mtime` / `last_heartbeat_seq` | 最后一次心跳的盘上读数 |
| `progress_actual` | **原进度的实际读数**：数据件实际行数／字节（⛔ 不抄进度标记里的自报值，§3 行 27） |
| `progress_declared` | 进度标记里的自报值（并列存档，供对账） |
| `active_count_after` | 回收后 `active/` 下条目数（应为 0；若为 1 说明有人又抢到了） |

**被回收的 agent 回来交件怎么办**：**⛔ 不直接进 Done**。

- 它的产物一律进 `verify` 列，由**复核席**独立核验（L1–L4，§B）。
- 若租约已被他人重新取得、且新持有者已产出 ⇒ 两份产物并列，进 `冲突` 卡（状态置 `阻塞`＋报警），由**人**裁；⛔ 不由 agent 自动择一、⛔ 不「后写的覆盖先写的」。
- 若无人接手、产物完整 ⇒ 走正常 verify→done 通路，但**回收事件保留在历史上**（可追责）。

### A.7 「单卡单执行者」的机制落点（不变量）

**INV-L1**：同一时刻，`cards/<id>/lease/active/` 下**未释放的租约条目 ≤ 1**。

- **靠什么保证**：① 取得＝原子创建（A.2）；② 释放/回收＝原子 rename，且**只由持有者或回收者**发起；③ 每次操作前后都把 `active/` 条目数写进事件。
- **机器可判**：`active/` 下条目数 ∈ {0,1} 合法；≥2 ⇒ **已破**，立刻报警（`BLOCKED`），暂停该卡的一切自动推进。
- **反空跑**：这条闸门必须配「故意塞两个租约目录，必须被抓住」的对照（§B.4）。

**INV-L2**：租约到期后持有者**不得**继续写该卡的事件（除非先重新取得租约）。靠 `owner.json` 的 `expires_at` 与事件里的 `lease_ref` 交叉校验；过期事件 = 非法事件（归约器拒收 + 报警）。

**设计决策**：`已定`（INV-L1/L2 的机制）。**待拍板**：回收权是否长期固定在发牌席，还是允许「全体 agent 可回收但必须留痕」（本席建议前者，单机单用户下更可追责）。

### A.8 与「引擎道租约」的关系（⛔ 两者不是同一件事）

| 维度 | 引擎道租约（既有正档 §6） | 看板卡租约（本件） |
|---|---|---|
| 保护对象 | 引擎**进程/官方校验**（同一时刻只能一个进程跑） | 卡片**执行权**（同一时刻只能一个 agent 干） |
| 占用判据 | 心跳 + `tasklist` 进程数=0 的释放实证 | 心跳文件 mtime + 租约目录存在性 |
| 时长量级 | **≤120s** 判占用 | 心跳 60s / TTL 600s |
| 层次 | 更底层（资源） | 更上层（任务） |
| 关系 | **可嵌套**：一个卡租约持有者在跑引擎动作时，**还要**再取引擎道租约 | 卡租约**不替代**引擎道租约 |
| 共同点 | 都用「盘上可判形制」取代口头让路；都⛔ 代写他席租约；件一律保留 | 同 |

⇒ **一张卡可以合法持有卡租约、却在引擎道租约上退出码 9 让路**；此时卡的进度停住但租约仍 fresh（agent 只是没在跑）。这与「心跳超时＝回收」不矛盾：心跳靠 agent 主动写，agent 在等引擎道时仍应写心跳。

## B 完成判据规范

### B.0 首要声明：退出码在这个体系里的位置

> **退出码＝诊断提示（hint），权重 0；⛔ 不作任何状态迁移的前置条件，⛔ 不进 Done 判定。**

三条理由：

1. **事实层**：F1 已证四家全可被证伪——Hermes 运行错也 RC=0；qoderclicn `subtype` 谎报 success；opencode 成败同码；codex 需读 JSONL。RC 连「进程有没有正常退出」都不总能答对。
2. **逻辑层**：RC 描述的是「**进程怎么结束的**」，不是「**世界上发生了什么**」。看板要判的是后者（文件在不在、内容对不对），拿前者当判据是范畴错误。
3. **治理层**：`orchestration-lessons.md` §7（行 55）「外部自证不进正档」——引擎回执属于**自证**；我方闸门复跑、两相并列后才采信。

**落成字段**：`evidence.kind=process_receipt` 里保留 `exit_code`，用途**仅限两件**：① 度量台账里统计「某引擎假绿灯率」（§2 行 18）；② 事后排障。它对 `done` 的贡献恒为**零**。

> ⚠️ 本件若出现「退出码 0 即成功」的判据，即触发派工单 §4 的 `FAIL`。此处显式写死：**不存在该判据。**

### B.1 分层判据 L1–L4（＋人位）

一层不过，不许进下一层；**层级只能取最严**。

| 层 | 名字 | 考什么 | 谁跑 | 机器可判？ | 不过的处置 |
|---|---|---|---|---|---|
| **L1** | **产物存在性** | 交付物路径存在；`Length > 0`；mtime 落在 `claim_at ≤ mtime ≤ harvest_at` 窗口内 | 机器 | 是 | 停在 `verify`，报「缺件/旧件」 |
| **L2** | **形制** | 字节数／行数／md5 前 8；编码（BOM／CRLF／非 ASCII／零字节）；`.json` 可 parse、`.md` 章节结构；⛔ 不看「命令没报错」 | 机器 | 是 | 打回施工席，记返工 |
| **L3** | **内容闸门** | 派工单声明的**必含项**逐条断言：章节标题在否、占位符零残留、术语白名单命中=0、非零计数出现、引号形态（中文强调用「」） | 机器 | 是 | 打回；每闸门必须带 A.4 式非零对照 |
| **L4** | **独立复核** | 复核席**另开会话**复跑 L1–L3＋**另找反例**：抽查数字与 URL（E-07 教训）、故意塞坏样例验闸门会红 | **复核席**（⛔ 不得是执行者） | 半（结论人写，过程机器） | 给 `PASS`／`FAIL`；`FAIL` 退回 `进行中` |
| **人位** | **拍板/评审** | 涉及拍板项、对外交付、红线争议 | **人**（红线 2） | 否 | 卡停在 `拍板` 列，⛔ agent 不得越过 |

**Done 的合取条件**：`L1 ∧ L2 ∧ L3 ∧ L4(PASS)` **且** 凭据三件齐（§C）**且** 无未决冲突 **且** 不涉人位 → 系统方可把卡从 `verify` 推进到 `done`。任一不满足 ⇒ 停在 `verify`（或按最严进 `阻塞`）。

> **本席对红线 1 的落点**：L1–L4 就是「盘上凭据」的具体化——**没有 L1–L3 的机器读数，连 verify 都进不去**；没有 L4 的独立复核，⛔ 不进 done。

### B.2 逐引擎结构化回执解析（⛔ 不写「统一解析」）

**总原则**：每家一个**版本化的解析器**；解析器只说三件事——① 本次「运行是否正常结束」，② 若异常，异常原因，③ 会话/模型等**元数据**。解析器**⛔ 不下「产物对不对」的结论**（那是 L1–L3 的事）。

| 引擎 | 结构化回执来源 | 判「运行正常结束」的字段 | ⛔ 不能用的字段 | 拿到「正常回执」**仍不算完成**的原因 |
|---|---|---|---|---|
| **Hermes** | `--usage-file <路径>` 的 JSON | `completed == true`（且 `failed == false`） | rc；单发 stdout 的「看起来说完了」（不带 `session_id`，不可回溯） | usage 只证「模型跑完了」，不证「文件落了」 |
| **codex** | `--json` 的 JSONL 事件流 | **必须见 `turn.completed`**；见 `turn.failed` 或 `type=error` 即失败；仅 `thread.started` **不算** | 只有 token 统计、没有终态事件的行 | JSONL 是过程日志；`turn.completed` 只证「这一轮没炸」 |
| **qoderclicn** | `-o json` 顶层对象 | `is_error == false`（初判）；`modelUsage` 核**模型是否回落** | **`subtype`**（会谎报 `success`，F1）；rc（仅 rc=1 可作**铁败**辅助） | `is_error` 是引擎自报；且无头下写权限可能**静默被拒**（P3 行 21） |
| **opencode** | `run --format json` 的 JSONL | 成功需出现 `type:"text"` **且正文含预期回执**；`type:"error"` 为失败 | **rc**（成功/失败**可能同码**，F1） | `run` 会持久化会话，失败运行也可能留会话；`--auto` 下默认放宽权限 |
| **RTOC**（外部信道，非 CLI） | HTTP 响应体 | HTTP 200 **且**回包非空 **且**围栏块内出现 `// FILE:` | ⛔ 不对全文做宽松正则（记忆 `rtoc-channel`「判成败」：拒答正文会写「换到能生成代码的模式就能拿到 // FILE:」，实测误判 4 份）；空回＝信道故障，⛔ 既不算成功也不算失败 | 它是「网页型无工具 AI」，无文件访问；体量超限会**静默空回且照计费** |

**逐引擎附加规则（为什么这样防得住）**：

- **Hermes**：`--usage-file` 是它**唯一**的盘上终态；没有 usage 文件 ⇒ 判 `未证`（⛔ 用 rc 补）。
- **codex**：要求 `--cd` 显式 + 前后比 `~/.codex/config.toml` 哈希（它可能改 trusted 段，P3 行 20）；配置被改 = 侧效应告警。
- **qoderclicn**：`subtype` 不可信 ⇒ 必须看 `is_error` 且**核 `modelUsage`**（防坏模型静默回落 auto）；「无头写权限可能静默拒绝」⇒ 即便 `is_error=false` 也要 L1 查文件。
- **opencode**：`explore/plan` 只是**软只读**（shell 可绕）；只读任务必须**硬 deny** `shell/edit/webfetch`，并核**最终文件差异**与会话 ID。
- **RTOC**：请求体每轮归档（否则「没回包」与「超限」分不清）；`529/503` 是**信道天气**，不消耗尝试次数。

**统一的地方只有一处**：不管哪家，回执**都只是 L1 的入场券**，不是 L1 本身。

### B.3 「假绿灯」怎么在机制上被抓住

**定义**（`orchestration-lessons.md` §2 行 17）：自报成功但交付件未落盘，或被写入凭证（mtime／SHA256／git diff）证伪。

**四道网（每道都给「为什么这样能防住」）**：

1. **时间窗对账**：凭据的 mtime 必须落在 `claim_at ≤ mtime ≤ harvest_at`。mtime **早于 claim** ⇒ 交的是**旧件**（或时钟异常）⇒ 报警。防「拿上次的成果冒充本次」。
2. **指纹复算**：L2 的 `length/md5` 必须能在**第二次独立调用**里复算一致（§C.2）。防「报告里的数字是编的」——因为复核席自己跑一遍，数字对不上就露馅。
3. **写入者一致性**：产物路径必须在**该席的领地白名单**内（§D 场景 4）；可选加 `git status/diff` 显示该路径确有改动。声明「我写了 X」但 git 显示 X **未变** ⇒ 假绿。
4. **自报 vs 实测并列，取最严**：引擎回执说「完成」＋我方闸门说「缺件」⇒ 判 **FAIL**（⛔ 不判「也许落了但没看见」），并把该引擎记入度量台账 `假绿` 列（§2 行 19 驱动降档）。

**⛔ 明确写死**：「文件存在 ＋ 引擎说成功」**不足以**判绿——必须过 L2／L3 的独立复算。这正是红线 1 与「外部自证不进正档」的交点。

### B.4 反空跑闸（什么叫「必须非零」的对照）

**定义**：任何「零命中／全过／0 失败」的结论，**必须**配一条**必然失败**的对照；对照没被抓住 ⇒ 结论作废（`BLOCKED`），⛔ 不是因为「件好」而放行。

**推荐的最小反空跑闸（3 条，直接可用）**：

| # | 闸门 | 「必须非零」的对照（control） | 对照没生效时 |
|---|---|---|---|
| AC-1 | **坏件注入** | 跑 L3 之前，先喂一条**已知违规的夹具**（如故意含 `TODO` 占位符／故意少 1 行／把 md5 改一位）⇒ 闸门**必须报红** | 报绿 ⇒ 闸门瞎了 ⇒ 整批 `BLOCKED`（比「全过」更严） |
| AC-2 | **分母非零** | `N of M` 的 **M 必须 > 0**；术语白名单扫描的「白名单条数」必须 > 0；扫描目录的「文件数」必须 > 0 | M=0（目录空／正则写错）⇒ 判 `BLOCKED`，⛔ 不判 `PASS`（§7 行 56：「0 命中」最常见是**尺坏**） |
| AC-3 | **正反样本并存** | 求「命中数」的扫描，必须同时输出一个**已知应命中**的样本被命中 | 已知样本未命中 ⇒ 尺坏 ⇒ 该扫描结果作废 |

**机器可读形制**（每个闸门输出）：

```
{
  "gate": "L3.placeholder-zero",
  "checked_count": 7,
  "failed_count": 0,
  "control_id": "AC-1.bad-fixture-01",
  "control_result": "caught"        // caught | missed
}
```
规则：`control_result != "caught"` ⇒ 该闸门结果**作废**（⛔ 不许把 `missed` 降级成告警）。

**具体例子（一道完整链路）**：某卡要求「交件含 A–E 五节」。
- 机器扫出 `五节命中=5/5` ⇒ 作废（没对照）。
- 加对照：造一份**只含 4 节**的夹具喂进扫描器 ⇒ 扫描器输出 `4/5, failed_count=1` ⇒ `control_result=caught` ⇒ 原结果 `5/5` 才是**可信**的。
- 对照若也报 `5/5` ⇒ 说明扫描器按「文件名」而不是「章节」判定 ⇒ 尺坏 ⇒ 整批 `BLOCKED`。

### B.5 提交（submit）事件的判据形状（把上面收成一个事件）

agent 交件时**不是**声明「我完成了」，而是**提交一组指向盘上事实的读数**：

```
submit 事件 = {
  card_id, lease_ref,
  artifacts: [ {path, length, md5, line_count} ],   // 它自己的读数（自报）
  engine_receipt: {engine, kind, fields...},        // B.2 的解析结果
  claims: ["L1", "L2", "L3"]                        // 它声称过了哪几层
}
```
⇒ 归约器只把它变成 `verify` 请求；**L1–L3 由机器**用**独立调用**重读盘上事实来判；**L4 由复核席**判。agent 的读数与机器读数不一致 ⇒ 优先怀疑两件事：agent 撒谎（记假绿），或**尺坏**（先疑尺，§7 行 56）。

## C 证据模型

### C.1 一条「凭据」长什么样（字段表）

一条凭据＝一个 JSON 文件（`evidence/<evidence-id>__<席号>.json`），字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `evidence_id` | string | 是 | 唯一 id（`EV__<card>__<seq>__<nonce>`） |
| `card_id` | string | 是 | 挂在哪张卡 |
| `event_ref` | string | 是 | 为哪次**状态迁移**作证（对应 `events/` 条目） |
| `actor` | object | 是 | 席号＋引擎＋模型＋`session_id` |
| `at` | 双读 `date`＋`epoch_ms` | 是 | **取自独立调用**（⛔ 不写「命令内事后补占」，§7 行 60） |
| `kind` | enum | 是 | `artifact`／`command`／`log_line`／`process_receipt`／`hash`／`human_approval` |
| `path` | string | 视 kind | 被证对象的路径 |
| `size` / `md5` / `line_range` | int/hex/[int,int] | 视 kind | **可被第三方复算**的量（存在性＋形制） |
| `cmd` | string | 视 kind | **可复跑的只读命令**（复现这条读数用） |
| `cmd_scope` | enum `read_only`／`write` | 是 | 写命令必须另有授权凭据 |
| `result` | object | 是 | 命令/解析的实际输出（截断留摘要＋完整件路径） |
| `tool_version` | string | 是 | 引擎/脚本版本（防「版本漂移后判据失效」） |
| `trust` | enum | 是 | `self_reported`／`machine_verified`／`human_signed` |
| `parent_evidence` | string / null | 是 | 上一条凭据 id ⇒ 形成**证据链** |

**为什么是这些字段**：`size/md5/line_range` 是「别人能重算」的量；`cmd` 是「别人能重跑」的入口；`trust` 把「自证」与「实测」显式分开（§7 行 55）；`parent_evidence` 让链断可查。

### C.2 凭据怎么可复跑（别人怎么验证它没造假）

**核验配方（三条独立读数，逐一对齐）**：

1. **存在＋尺寸**：`Test-Path <path>` 且 `(Get-Item <path>).Length == evidence.size`。
2. **指纹**：`Get-FileHash -Algorithm MD5 <path>` 前 8 与 `evidence.md5` 一致。
3. **行数**：用**独立工具**读（`Get-Content <path> | Measure-Object -Line`），⛔ **不采信**凭据里的自报 `line_count`（§2 行 29：续跑席手算字节错 2 的先例）。

**时刻怎么核**：只用**文件系统 mtime**（`(Get-Item).mtime`）与凭据窗口比；凭据里的 `at` ⛔ 不作时效依据（§3 行 28：实测有席把时刻写死、120 条共用一个时间戳）。

**链式自证**：第 N 条凭据的 `parent_evidence` 指向第 N-1 条，且第 N 条文件本身也被哈希进第 N+1 条 ⇒ **断链/改旧件必被察觉**。

**反空跑**：核验本身也要过 AC-1（故意改一位 md5，核验器必须报不一致）。

### C.3 凭据与卡片状态的绑定关系

- **一次状态迁移 = 一个事件文件**（`events/<seq>__<verb>__<actor>__<nonce>.json`），事件**必须**带 `evidence_ref: [evidence_id...]`。
- **归约器规则（红线 1 的技术落点）**：任何事件若 `evidence_ref` 为空 ⇒ **非法**：卡停在原状态 + 报警 + 该事件进 `logs/` 待查。⇒ 「模型说完成了」**在数据层就无法变成 Done**。
- **历史 append-only**：事件只增不改。更正＝新增一条 `corrected_by` 事件并**引用**被更正事件 id；⛔ 不改写旧事件（§11 行 92「⛔ 不改写历史掩盖」）。
- **派生快照可弃**：`_index/` 与 Web 看板的 DB 一律**可弃可重建**；快照与事件流不一致 ⇒ **以事件流为准** + 报警（快照⛔ 不是真相源）。
- **状态变更时凭据怎么写进历史**：事件的 `evidence_ref` 直接指 `evidence/<id>.json`；该凭据的 `event_ref` 反向指回事件 ⇒ 双向可查，任一侧缺失即报警。

## D 失败场景推演（12 个；每个给 场景／机制怎么响应／是否留痕／判定）

> 前 8 个＝派工单 §2.1(D) 点名必含；后 4 个是本席补的（防「凑数只写场景不给机制」——派工单 §4 的 `FAIL` 项）。

**S-1 · 两个 agent 同时抢同一张卡**
- **响应**：两者同时对 `lease/active/L__…/` 做原子创建 ⇒ 恰好一个成功（A.2）；失败者收到「已存在」，**读回**对方 `owner.json` 得持有者信息后退出。
- **留痕**：成功者的事件 `claim`；失败者写一条 `claim_denied` 事件（含竞争对方 lease_id）。
- **判定**：`active/` 条目数=1 ⇒ `PASS`；=2 ⇒ `FAIL`（INV-L1 破，报警）。

**S-2 · agent 干到一半进程被杀**
- **响应**：心跳停止 ⇒ 经 `stale`→`expired`（A.5）⇒ 发牌席按 A.6 回收；产物若已部分落盘，**按数据件实际行数**记进度（⛔ 不抄进度标记自报值，§3 行 27）。
- **留痕**：`reclaimed/L__…/reclaim.json`（原持有者／会话 id／回收者／时刻／实际进度）。
- **判定**：`reclaimed` 存在且 `active/`=0 ⇒ `PASS`（回收合规）；无 `reclaim.json` 而 `active/` 空 ⇒ `未证`。

**S-3 · agent 自报完成但文件没落盘**
- **响应**：L1 查无该路径／`Length=0` ⇒ 停在 `verify`；引擎回执与实测并列**取最严**（B.3 第 4 道网）⇒ `FAIL`，记假绿。
- **留痕**：`submit` 事件（含 agent 自报读数）＋机器 L1 读数（缺件）两件并列进 `evidence/`；度量台账 `假绿`＋1。
- **判定**：`FAIL`（⛔ 不判「也许落了」）。

**S-4 · agent 越界写了领地外的文件**
- **响应**：产物路径必须在该席领地白名单内（卡契约声明）；越界 ⇒ L2/L3 阶段判非法，卡进 `阻塞`；⛔ 看板**不代删**越界文件（越界文件属外部件，删除是红线 10 的不可逆操作，须人放行）。
- **留痕**：越界路径／时刻／写入者写进事件 + 报警；附「交接单」给人处置。
- **判定**：`BLOCKED`（⛔ 不自动回滚）。

**S-5 · 心跳还在但 agent 实际卡死**
- **响应**：心跳是**意愿证明**、不是**活着证明**（A.5）。若心跳仍在写但 `heartbeat_seq` 停滞／进度无推进 ⇒ 判 `stale`（黄）报警；若心跳完全停 ⇒ 走 S-2。**回收前**可选加一次「活性探测」（如 `tasklist` 查该引擎进程；⛔ 不用 CLI 交互探测）。
- **留痕**：`stale` 变色＋报警事件（含 `heartbeat_seq` 与进度读数）；若回收，走 S-2 留痕。
- **判定**：仅停 `stale` 不回收 ⇒ `待拍板`（回收员按阈值定）；回收 ⇒ 同 S-2。
- **已知残留**：agent 若「假装还在写心跳」而实际卡死，本机制**抓不住**（见 §E 剩余风险 R3）。

**S-6 · 人拍板后 agent 想改回去**
- **响应**：`拍板/评审` 列只有**人**能推进（红线 2）；agent 对已拍板项只能**新增**「异议/复议请求」事件，⛔ 不得改状态、⛔ 不得改历史（append-only）。复议是否受理⇒**人**定。
- **留痕**：`reopen_request` 事件（引用原拍板凭据）＋人是否受理的 `human_approval` 凭据。
- **判定**：状态未变、请求留痕 ⇒ `PASS`；状态被 agent 改动 ⇒ `FAIL`（红线 2 破）。

**S-7 · 凭据指向的文件事后被改**
- **响应**：复跑核验（C.2）时 `md5/长度` 与凭据不符 ⇒ 立刻报警；凭据链断裂（`parent_evidence` 哈希对不上）⇒ 报警。判「凭据失效」，**该凭据支撑的状态迁移降级为待复核**。
- **留痕**：差异读数（旧 md5 vs 新 md5）＋检测时刻进事件；附 git 历史（若有）供追。
- **判定**：`FAIL`（凭据被证伪）或 `未证`（无法判定改动者）。

**S-8 · 租约持有者失联后又回来交件**
- **响应**：其租约已 `reclaimed`。回来交件 ⇒ ⛔ 不直接进 Done；一律进 `verify` 由复核席独立核验（A.6）。若已有人重新持有并产出 ⇒ 两份产物并列，进 `冲突`，由**人**裁。
- **留痕**：`late_submit` 事件（引用原租约与回收记录）＋冲突卡事件。
- **判定**：无冲突且过 L1–L4 ⇒ `PASS`；有冲突 ⇒ `BLOCKED`（待人裁）。

**S-9 · 看板接口层／归约器自身崩了（本席补）**
- **响应**：归约器只是**派生**方，⛔ 不是真相源（C.3）。崩了 ⇒ 重建索引（从 `events/` 全量重放）；重建结果与崩溃前快照不一致 ⇒ **以事件流为准** + 报警。归约器自身用**引擎道式独占租约**起（单实例），防两个归约器同时写 `_index/`。
- **留痕**：崩溃时刻／重建前后条目数进 `logs/`；不一致项列清单。
- **判定**：重放后可完全复原 ⇒ `PASS`；复原不出（events 残缺）⇒ `BLOCKED`。

**S-10 · 两个席并发写同一个产物路径（本席补）**
- **响应**：违反 F5「一文件一写者」。L2 的 mtime 对账＋（可选）git 变更检查会暴露「同窗口两席都写了该路径」；命名规程要求产物带席号（`__<席号>__<口径>`），从命名上就应避免撞名。
- **留痕**：两席各自的 `submit` 读数并列 ⇒ 冲突事件 + 报警。
- **判定**：`BLOCKED`（⛔ 不「后写覆盖先写」）。

**S-11 · 时钟跳变／时刻不可信（本席补）**
- **响应**：一切时效判据**以文件系统 mtime 为准**（A.5），自报 `epoch` 只作参考；若自报与 mtime 差 > 容差 ⇒ 报警。若系统时钟整体跳变 ⇒ mtime 也会跳，此时**冻结自动回收**（改人工），避免误回收正持有者。
- **留痕**：报警事件（含两组读数）；冻结动作留痕。
- **判定**：报警＋冻结 ⇒ `PASS`（机制接住）；静默误回收 ⇒ `FAIL`。

**S-12 · 卡停在「拍板」列但人不在场（本席补）**
- **响应**：⛔ agent 不得代推进（红线 2）。看板只**呈现**待拍板项（截图/人话清单/门禁数字/≤3-4 个选项，用户带宽约束）；超时**不自动放行**，只升级为「提醒」（⛔ 不做桌面弹框／通知——未经当场同意不得在真实桌面产生可见物）。
- **留痕**：停留时长计入卡的风险字段（「阻塞原因」）。
- **判定**：状态保持 ⇒ `PASS`；任何自动越权 ⇒ `FAIL`。

## J 一页人话版（给产品主看）

1. **两个人同时抢一张卡怎么办？** 不让谁「先读到没人就抢」，而是让他们同时去**新建同一个文件夹**——系统保证只有一个建得成。谁建成了谁拿到，另一个当场就知道没戏。不靠运气、不靠先来后到的时间差。
2. **人失联了怎么办？** 干活的人每分钟留个「我还活着」的小纸条（**新写一张**，不覆盖旧的，否则看不出该不该回收）。十分钟没新纸条＝失联，由**发牌的人**回收，回收时把「原来是谁、什么时间、干到哪」全部记下来。
3. **什么才算干完？** **不看「程序退出码」**——本机四个 AI 引擎的退出码全都可能骗人。要看四样：文件在不在 → 尺寸对不对 → 内容合不合要求 → **另一个席位的 agent 独立复查过**。四样齐了才叫干完。少了任何一样，就停在「待验收」，不进「完成」。
4. **怎么防止「嘴上说干完了」？** 每一样结论都要能指到「第几个文件、多少字节、哪一行」，而且换个人**照着命令重跑一遍能得出同样的数**。谁报的数跟实测对不上，就判没干完，并且记一笔「这引擎爱吹牛」。
5. **会不会误判？** 每个检查都配一个「故意放个坏例子进去，检查必须报警」的对照；对照没报警，说明**尺子本身坏了**，那批结论全部作废、重来——宁可说「没验」，绝不说「全过」。
