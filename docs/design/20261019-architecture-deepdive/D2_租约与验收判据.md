## 2 任务

解决两件「不做就全是空话」的事：**认领怎么防重**、**完成怎么算数**。

### 2.1 必须产出

**(A) 认领协议（租约）**
- 两个 agent **同时**抢同一张卡，机制上怎么保证只有一个成功？（给出具体的原子性做法，文件形态下尤其要正面回答）
- 租约的字段：持有者／取得时刻／到期时刻／心跳间隔／续约次数上限
- **心跳超时判定**：多久算超时？依据是什么？（参考既有正档的 120s，但要说明为什么这个数适用于看板）
- **回收流程**：谁有权回收？回收要留哪些痕（原持有者／回收者／时刻／原进度）？被回收的 agent 回来交件怎么办？

**(B) 完成判据规范**（本席最难的一节）
前提事实：**四个引擎的退出码全都不可信**（Hermes 运行错也 RC=0；qoderclicn `subtype` 会谎报；opencode 成功/失败同码）。所以：
- 「完成」到底看什么？给出**分层判据**（至少：产物存在性／形制／内容闸门／独立复核）
- **退出码在这个体系里应该处于什么位置**（提示？证据之一？完全不用？给出理由）
- 每种引擎各自的**结构化回执**该怎么解析（逐家给判据，别写「统一解析」了事）
- **反空跑闸**怎么设计：什么叫「必须非零」的对照？举一个具体例子
- **假绿灯**（自报成功但没落盘）怎么在机制上被抓住？

**(C) 证据模型**
- 一条「凭据」长什么样？（给字段）
- 凭据怎么**可复跑**？（别人怎么验证这条凭据没造假）
- 凭据与卡片状态的绑定关系（状态变更时凭据怎么写进历史）

**(D) 失败场景推演**（≥8 个，每个给：场景／机制怎么响应／是否留痕）
必须包含：两 agent 同抢／agent 干到一半进程被杀／agent 自报完成但文件没落盘／agent 越界写了领地外的文件／心跳还在但 agent 实际卡死／人拍板后 agent 想改回去／凭据指向的文件事后被改／租约持有者失联后又回来。

**(E) 与红线的对照**
红线 1（状态即证据）与红线 3（认领即租约）各自怎么落地；剩余风险。

## 4 完成判定

- `PASS`：五节齐全；认领协议给了**具体原子性做法**（不是「加个锁」了事）；完成判据**逐引擎**给了判据；失败场景 ≥8 且每个有响应与留痕；含非零计数。
- `BLOCKED`：输入不可读。
- `FAIL`：用「退出码＝0 即成功」当判据；或失败场景凑数（只写场景不给机制）。
