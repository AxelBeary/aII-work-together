一、v2 的适配器真能消掉双写吗？——能（结构性），但「闭包→diff→内核命令」有 4 处失真（均已读代码）：
1. diff 对象错了：05 稿 §3.1.3 写「对返回值做 diff」。mutator 返回值只是 touched tasks，多处以「返回 [] 仍提交」表达真实变更：routes.ts:1093-1097（purge 删除整卡返回 []）、:1527-1530（settings 返回 []）、session-sync.ts:420-429（splice 清卡返回 []）、external-sync.ts:57/110/218/287。按返回值 diff = 这些写全部静默丢失。必须对整个 draft 做 before/after 深比较。
2. 复合原子闭包拆开会撕裂：routes.ts:970-986（move+comment 一体）、:1428-1444（ledger-replaced 一次闭包改 tasks+externalSync+settings 三块）、execution.ts:580+（run gate 一次闭包完成认领+翻 in_progress+开 execution 记录）。「按 kind 映射命令」若拆成多条内核命令即丢原子性；若合并为整文档 upsert，内核侧校验就变成校验整个文档，T0 第三列的写法要跟着变。
3. 无命令可映射：52 处中约 30 处（session-sync 9、execution 9、tools 8、routes 的 comment/checklist/settings/import）落不到内核现有写命令族（board.py claim/submit/heartbeat/release/create_card + server.py:797-802 的 /api/card /api/human /api/bulk）。内核 cards 表（storage.py:40-63）没有 comments/executions/checklist/settings 承载位——自动改 title、插 execution 记录、标 deliveredAt 全都映射不到。T0 三列清单第三列会大面积空。
4. kind 是 9 种不是 8 种：05 稿 §2 表格「按代码以 8 为准」错了——store.ts:32 LedgerChange['kind'] 明确含 'external-sync-updated'。发牌席的复跑 grep 正则 '(task|comment|execution|settings|ledger)-[a-z]+' 匹配不到 external，属于量具漏检。external-sync 虽摘除，但 routes.ts:1428 的 ledger-replaced 仍写 ledger.externalSync（:1437-1438），T0 必须列。
必加的一条保护：KernelStore 内存副本的唯一前进来源＝内核回执/事件流；闭包跑过的 draft 只用于生成命令、绝不直接成为副本状态（否则成功后 diff 偏差（version/updatedAt）逐渐漂移、内核拒绝后污染会随下一次 mutate 带出——「延迟双写」）。
