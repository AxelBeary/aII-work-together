## B 状态机（`board.py:104`）

`待认领 / 进行中 / 待返工 / 阻塞 / 待验收 / 核验中 / 拍板中 / 完成 / 已取消`

合法边（`board.py:108-121`）：只有 agent 能走 待认领→进行中、待返工→进行中、进行中↔阻塞；只有 review 能走 待验收→核验中、核验中→完成/待返工；只有 human 能走 拍板中→完成/待返工、→已取消。

## E T0 四列表的填写规则（分席必须照做）

每一行 = 一个 `store.mutate` 调用点，四列：

1. **kind**：`task-created | task-updated | task-moved | task-deleted | comment-added | execution-recorded | settings-updated | ledger-replaced | external-sync-updated`（**9 种**，`store.ts:32`）
2. **实际变更**：这个闭包到底改了什么（读代码写，⛔ 不按 kind 猜）
3. **内核命令**：A 表 1-10 里哪一条；**没有就写 `缺口`**
4. **内核侧校验**：这条命令自己的闸（如 claim 的 epoch CAS、submit 的 L1-L4、review 的异会话+证据）

**反空跑三条：**
- 行数必须 = 该文件 `grep -c 'store.mutate('` 的复跑值；少一行即 FAIL。
- 「缺口」列为 0 时，必须贴出逐行映射证据；⛔ 不许写「都能映射」。
- 每条「缺口」必须给出：缺的是**命令**还是**承载位**（C 表），二者处置不同。
