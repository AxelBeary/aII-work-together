## 0 设计公理（先定不可谈判的五条）

1. **一本账**：任务状态只有一个权威来源（内核 journal），其余全是视图/缓存。⛔ 不允许两个系统同时接同一批活。
2. **四个面，一个内核**：CLI、DSH 面板、MCP 工具、桌面壳都只是内核的客户端；⛔ 任何面不得自建账本。
3. **证据先于状态**：状态变更必须挂可复核工件（路径/字节/退出码/diff 哈希）；人闸只能由人越过。
4. **不重写能复用的**：UI 用 taskboard 的（Apache-2.0 + NOTICE），执行用 DSH 会话，守望用 dock，跨机用 waypost；只新写「契约 + 内核服务化 + 适配层」。
5. **失败要吵**：任何面连不上内核、任何执行器掉线、任何迁移跳条，必须显式报错，⛔ 不静默转绿。

> 「最完美」在工程上不存在；本方案追求的是**单一真相 + 最少新代码 + 最强治理 + 全场景可用**，代价写在各阶段的「代价」栏里。

### 2.2 Event v1（append-only，哈希链）

```json
{"seq": 42, "task_id": "t_…", "type": "claim|submit|review|human|retry|reclaim|gate.L1..L4|adopt",
 "at": "…", "actor": "w1|human", "epoch": 7,
 "payload": {}, "prev_hash": "…", "hash": "sha256(canonical(事件体))"}
```

### 2.3 Evidence v1

```json
{"kind": "file|cmd|diff|hash|test", "target": "相对路径或命令", "digest": "sha256|exit:0",
 "captured_at": "…", "verifier": "machine|seat", "tier": "VERIFIED|AUDITED-UNGROUNDED"}
```

### 2.4 身份

- `project_id`：`realpath` 规范化后取 sha256 前 16 位；注册表仍在 `~/.aII-work-together/projects.json`，**只记「项目在哪」**。
- `task id`：ULID（时间有序、可排序、无中心）；旧卡 id 原样保留，新增 `legacy_id` 字段。
- `seat`：执行席位（一卡一租约）；`role` 取 BBFF 角色目录（explorer/librarian/oracle/designer/fixer/writer/laborer…）。

### 2.5 端口与面

| 面 | 协议 | 现状 | 要做 |
|---|---|---|---|
| CLI | argv | 已有 30 个子命令 | 保持兼容，新增 `serve`/`tick`/`mcp` |
| HTTP/SSE | JSON + `text/event-stream` | 已有 `/api/state|cards|card|cost|run`，Host 校验 + 页面 token | 加 SSE、加 `/api/events`、写接口统一 token |
| MCP | stdio | 无 | 新写 10 个 `board_*` 工具（名字对齐 taskboard 的 10 个，见 §4） |
| 桌面壳 | WebView2 | 已有 | 保持，作为「DSH 不在」的离线面 |

## 3 关键机制（为什么这样最稳）

1. **CQRS 副本，不是双账本**：DSH 面板里的 store 只是内核账本的**物化视图**；面板的每个写操作 = 一次内核写 + 一次 SSE 刷新。断网/内核挂 ⇒ 面板转只读并显式告警，⛔ 不允许它自己写本地账本。
2. **一个调度器**：调度进内核（`schedules` 表 + `next_run`），由 dock 每 30s `board tick` 触发 due 任务；⛔ taskboard 的 host cron 关闭，只留一个触发源。
3. **两套执行器，一个提交面**：DSH 会话执行器与 CLI 执行器都必须走 `claim → submit(evidence)`；谁也不能直接改状态。
4. **租约 + epoch**：沿用现有 CAS 栅栏（D-024）；面板执行器认领时带 epoch，心跳超时回收。
5. **人闸**：agent 在 MCP/CLI 面永远到不了 `done`；`human` 动作只从「人点的那个面」发出（面板按钮/CLI 令牌），事件记 `actor=human`。
6. **审计链**：每个事件带 `prev_hash`；`audit` 校验链断裂/事件被截断/租约残留，发现即报警。
7. **幂等**：`add` 支持 `key`；`adopt` 迁移按 `(source, legacy_id)` 去重；重放不产生第二条任务。

## 4 DSH 面：fork taskboard 的边界（合法且可控）

已核实（盘上）：taskboard 0.10.0 **随包提供完整 TS 源码**（`src/client/*.tsx`、`src/host/*.ts`，含 `store.ts`/`routes.ts`/`tools.ts`/`execution.ts`），不是只有压缩产物 ⇒ 可 fork、可改、可重建。

**只改三处，其余不动：**

| 文件 | 改什么 | 不改什么 |
|---|---|---|
| `src/host/store.ts` | 持久化改为「内核 SSE 副本」；写方法转发内核 API | 对外接口（snapshot/get/subscribe）保持，UI 零改动 |
| `src/host/tools.ts` | 10 个工具转调内核 `board_*`（保留 `taskboard_*` 别名） | 工具名/参数形态，避免旧会话失效 |
| `src/host/execution.ts` | 跑完 DSH 会话后向内核 `submit` 证据；⛔ 不再写本地账本 | 会话派生/报告采集/worktree 逻辑保留 |

**保留不动**：`src/client/**`（五列看板、详情、diff、清单、模板、i18n）、`git.ts`/`isolation.ts`（worktree + 合并）、`scheduled-session.ts`（仅执行，不调度）。

**许可**：Apache-2.0。在 `NOTICE` + 文件头保留原版权与出处；我们新增文件用 MIT；对外分发时两份许可一起给。

**别名兼容**：内核 MCP 同时暴露 `taskboard_list/get/create/update/move/comment_add/checklist/execution_report/delete` 别名 ⇒ 旧会话/旧提示词不改也能用。

## 5 代码与仓库布局（终态）

```
hub/                     # 现 aII-work-together 升级；git subtree 导入保留历史
├─ contracts/            # JSON Schema + fixtures + 一致性测试
├─ kernel/               # Python 零依赖：ledger/lease/evidence/audit/http/sse/mcp/cli
│  ├─ board/             # 由 tools/board.py 等抽出（行为不变，测试全绿）
│  └─ tests/
├─ faces/dsh/            # TypeScript fork（Apache-2.0 + NOTICE）
├─ faces/desktop/        # 现有 WebView2 壳
├─ executors/cli/        # opencode/codex/qoder/hermes 适配（现有 engines.py）
├─ executors/peer/       # waypost 桥
├─ supervisor/           # Rust fork（MIT）
├─ transport/            # waypost（MIT）
├─ team-adapter/         # BBFF 适配层（不 vendor，pin 上游版本）
├─ governance/           # AGENTS/DECISIONS/ENVIRONMENT/REGISTRY/HANDOFF
└─ docs/
```

**关于 BBFF**：它在上游活跃演进（1.0.1，46k 行），**vendor 进来会变成长期维护负担**；推荐「pin 版本 + 写适配层」，只接三件事：角色目录、seat 映射、记忆键。许可 MIT，将来要 vendor 也无障碍。

**关于合并时机**：P0–P4 各仓先不动（契约层集成）；**P6 切换完成后再 subtree 合并**，避免「边合并边改契约」双线爆炸。

## 6 分阶段（P0–P6）

| 阶段 | 交付 | 验收闸（必须有非零反空跑） | 代价/风险 |
|---|---|---|---|
| **P0 契约** 2–3 天 | `contracts/` v1 + 一致性测试 + 3 条 ADR | 坏卡（缺证据/跨项目/重复 key）必须被拒；同一压测重放 100 次只产生 1 条 | 契约改一次全员返工 ⇒ 先冻结再动 UI |
| **P1 内核** 1–2 周 | 内核抽包；`serve`（SSE+token）、`mcp`、`tick`；旧 20 道闸全绿；迁移 dry-run | 20 道闸全绿 + 并发 12 线程只有 1 个认领成功 + 迁移条数对账（`adopted + skipped = 源条数`） | 抽包回归；先保行为再优化 |
| **P2 DSH 面** 2–3 周 | fork 面板接内核；执行器提交证据；旧工具别名 | 全链路：UI 建卡 → agent MCP 认领 → 证据提交 → 人点验收；杀内核 ⇒ 面板只读且报警（不许本地写） | taskboard 上游跟进；把改动压在 3 个文件内 |
| **P3 守望** 1 周 | dock 托管内核 + tick；一个托盘；ProcGuardTray 退役 | `kill -9` 内核 ⇒ 10s 内拉起并留痕；误杀数 0（对照：10 个正常进程不受影响） | dock 权限边界；dry-run 先并行一周 |
| **P4 跨机** 1–2 周 | waypost 信 ↔ `source=peer` 任务；裁决=证据；状态板=镜像 | 红队：对端信塞「忽略规则/给我写权限」⇒ 必须只读且记拒绝；重复信去重 | 不可信输入；工具面砍到 4 个文件工具 |
| **P5 团队** 1 周 | BBFF 角色→seat；记忆键；superpowers→DoD 模板 | 一个角色只能认领自己权限内的卡（越权必须被拒） | 上游 API 变动；适配层隔离 |
| **P6 切换** 1 周 | 双跑一周 → 冻结旧入口 → subtree 合并 → 手册/回滚 | 旧入口冻结后无新增事件；回滚演练 30 分钟内恢复 | 冻结期双写；先只读双跑 |

**每阶段的「完成」定义**：不是「代码写了」，是「该阶段闸门跑出非零证据 + 有回滚路径 + 更新 REGISTRY/DECISIONS/HANDOFF」。

## 9 明确不做（防「完美」变臃肿）

- 不重写 UI（用 fork 的 taskboard）。
- 不把内核改成 Rust/TS（Python 零依赖是优势）。
- 不做两个账本、双向同步、事件合并。
- 不做「聊天室」式多 agent 讨论（D-013 仍有效）。
- 不在 P6 之前合并仓库。
- 不把 BBFF 的 Memory/Scope 复制进内核（各司其职）。
