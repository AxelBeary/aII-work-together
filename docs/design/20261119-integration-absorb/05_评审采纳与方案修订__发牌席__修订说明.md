## 3 采纳的修订

### 3.1 §4 改写：不换心脏，装适配器（KernelStore）

原 §4「fork 后只改 3 个文件」作废。新边界：

1. **新增一个文件** `src/host/kernel-store.ts`，实现 TaskStore 对外同样的一组方法（`load/snapshot/get/subscribe/read/mutate/location`）。
2. **本地零持久化**：`persistAtomic` 直接抛 `ReadOnlyLedger`；只保留 `.dump()` 供迁移。断网 = 只读 + 报警，**结构上不可能双写**（这一条是 B 席的关键建议，采纳）。
3. **`mutate(kind, mutator)` 的转发**：在内存副本上跑闭包 → 对返回值做 diff → 按 kind 映射成内核命令（见 3.2 的 T0 清单）→ 带 `epoch`/token 发内核 → 内核拒绝则抛错、副本不前进。闭包绝不跨进程。
4. **UI 与 routes 零改动**：`TaskBoard.tsx` / `TaskDetail.tsx` / `routes.ts` 保持原样；52 处调用点全部自然收敛到 `kernel-store.ts`。
5. **调度只留一个**：`scheduler.ts` 降级为纯读（10 处写路径全部删）；触发源改为内核 `tick`。
6. **摘掉第二写面**：`external-sync.ts`（禅道/TAPD，5 处写）在 P2 直接摘除；将来要接，走内核 `source=` 入库，不再让面板直写。
7. **构建基线先行**：发布包没有构建链，P2 第一步是 `git clone` 上游 0.10.0 + 建立可构建基线 + 一次性 upstream diff 脚本；否则「fork」只是改 `lib/*.js`。
8. **跨项目**：面板是全球单板，内核是按项目分库。适配器按 `workspaceId ↔ project_id` 扇出读、按 `project_id` 定向写；快照合并加 `project_id` 字段。这一条进 T0。

### 3.3 §3 改写：不要 CQRS，要「只读内存副本」

- 面板本地只做**只读副本**（无持久化、无回放、无本地账本）。
- 同步用 `GET /api/events?since=seq` 轮询（5–30s）；SSE 推迟到 P2 之后，不作为 P0 前提。
- 首次加载 = 按项目扇出 `/api/cards` 合并。
- 内核写成功才更新副本；失败则 UI 报错，副本保持原状。

### 3.4 §6/§7 闸门增补（P0–P2）

| 阶段 | 新增闸门（必须非零） |
|---|---|
| P0 | ①`lease.epoch` 进 HTTP 契约：两个 epoch 并发提交，**恰好 1 条落库**；②`idempotency_key` 全局唯一索引，重放 100 次只 1 条；③`project_id` 跨项目拒绝有测试；④`schema_version` 读回 + 未知版本拒绝启动 |
| P1 | ⑤`PRAGMA user_version` 读写 + `VACUUM INTO` 备份/恢复演练（损坏账本 30 分钟内恢复）；⑥读写锁拆分（SSE/轮询不持写锁）；⑦per-face 凭据（CLI/面板/MCP 各一把，泄漏只失一面） |
| P2 | ⑧`KernelStore` 里 agent 面 upsert 到 `done` 必须被内核拒绝并留事件；⑨杀内核 ⇒ 面板只读且报警，⛔ 无本地写；⑩批量勾选 20 项只产生 20 条事件、不撕裂 |

### 3.6 §9 简化（采纳两席共同意见）

- **不做 subtree 合并**：hub 只放 `contracts/` + `adapters/` + `governance/`；各组件留在原仓，用版本矩阵发布。省掉 Apache/MIT 混仓与 4.7 万行 vendor 负担。
- **MCP 别名推迟**：先做 10 个正名工具；`taskboard_*` 别名等真有旧会话需要再补。
- **P5（BBFF role→seat）降为可选**：seat 已够用；等真出现「按角色限权」需求再做。
- **摘除 external-sync**（见 3.1）。
- 保留：dock 守望、waypost 跨机、桌面壳离线面。

### 3.7 新发现的缺口（进 P0/P1）

1. **per-face 凭据**：现在只有页面级单 token（`server.py:67`），面板/MCP/CLI 共用 = 一面泄漏全线失守。
2. **备份与 WAL 撕裂**：没有备份/恢复闸；dock `kill -9` 后 SQLite WAL 尾部恢复路径未写。
3. **schema 演进**：`SCHEMA_VERSION` 只写不读；旧事件 v1→v2 怎么读无方案。
4. **全局 revision vs 分项目内核**：面板是全球单板，内核按项目分库；适配器必须扇出合并（T0 票）。
5. **HTTP 认领缺 epoch**：现在 epoch 只在 CLI 层校验（`cli.py:674-680`）；面板执行器与 CLI 执行器可同时认领。

## 7 2026-11-19 追加：B2 复评采纳（v2.1）

> 来源：06_独立评审_B2_GLM53__评审席C__回执.md（cross-session，GLM 5.3，只读）
> 我抽验：store.ts:32 的 kind 联合、routes.ts:1093/1527/1428、session-sync.ts:370/420、execution.ts:580、storage.py:40-63、server.py:797-802 —— 与 B2 指认一致，全部复现。

### 7.1 更正（我错了）

- **kind 是 9 种，不是 8 种**：`external-sync-updated` 在 `store.ts:32`。我 §2 的 grep 正则漏了 `external`，属量具漏检；复跑直接读 union 或 `grep external-sync-updated`。
- **diff 对象错了**：不是「mutator 返回值」，而是**整个 draft 的前后深比较**。返回值只是 touched tasks，多处「返回 [] 仍提交」：routes.ts:1093（purge）、:1527（settings）、session-sync.ts:420（清卡）、external-sync.ts:57/110/218/287。
- **副本前进规则（必加）**：KernelStore 内存副本**只从内核回执/事件流前进**；闭包跑过的 draft 只用于生成命令，绝不直接成为副本状态（否则 version/updatedAt 漂移，内核拒绝后的污染会被下一次 mutate 带出——「延迟双写」）。

### 7.2 v2.1 增补（只列改变决定/测试的）

| # | 改动 | 非零断言 |
|---|---|---|
| 1 | T0 加第四列「内核命令缺口」：逐条标注现内核 API 是否存在 | 缺口为 0 必须贴出全部 52 条映射证据；否则报缺口数 ≥1 |
| 2 | 「返回值 diff」→「整 draft 深比较」 | routes:1093 / :1527 / session-sync:420 三种「返回 [] 写点」行为等价测试，diff 必须非零 |
| 3 | P2 闸门扩展：agent 面任何非 add/claim/submit 语义写（非 todo 状态、写 claimedBy、插 execution）必须拒并留事件 | 拒绝计数 ≥3（对应 session-sync 三个自动置 in_progress 点） |
| 4 | kind 更正为 9，复跑正则补 `external` | `grep external-sync-updated store.ts` ≥1 |
