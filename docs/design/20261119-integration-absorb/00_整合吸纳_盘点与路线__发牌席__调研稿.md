## 1 结论先行

1. **这六件不是六个产品，是三个层次 + 一个没接上的面**：任务/编排层（本仓看板、taskboard、BBFF）、守望层（sentinel-ops → sentinel-dock）、跨机层（waypost）。缺的不是功能，是**一个账本、一个身份、一个总入口**。
2. **最该先做的不是合并代码，是定契约**。现在有 **4 套「任务真相」、3 套执行器、3 套调度、3 个托盘**；先并代码只会把 4 份真相焊死在一起。
3. **推荐终态**：本仓的 board 内核当唯一账本（它已有租约/证据分级/人闸/审计/续跑），DSH 侧只做**客户端面**（不 fork taskboard），sentinel-dock 当唯一常驻守望，waypost 当远程执行臂，BBFF 只保留「角色/记忆/权限」三件事。详见 §5 方案 A。

## 4 冲突面（不解决就会互相拆台）

1. **4 份任务真相**：本仓 `board/board.db`、taskboard `dsh-taskboard.json`、BBFF 会话内 team tasks、waypost 状态板。任何两份同时接同一批活 ⇒ 双认领、双执行、双记账。
2. **3 套执行器**：`tools/engines.py`（无头 CLI）、DSH 会话（taskboard/BBFF）、waypost 的 hermes。同一任务可能被两个执行器各跑一遍。
3. **3 套调度**：board orchestrator 循环、taskboard host cron、dock 插件调度（外加 DSH 自带 schedule）。同一时刻谁触发没有唯一答案。
4. **3 个托盘**：board 托盘、ProcGuardTray、dock 托盘。整合后必须只剩一个常驻入口。
5. **2 套写权语义**：board 的 lease/epoch 与 taskboard 的 claim/hold 各自成立，但**跨系统不复用**；「一个路径一个写者」这条红线会被绕过。
6. **2 套完成定义**：board 的 `evidence_tier` 与 taskboard 的「清单全勾 + 人验收」。对外只能有一个「已验证」口径。
7. **许可**：`sentinel-ops` **没有 LICENSE**（对外分发前必须补）；taskboard 是 Apache-2.0（fork/复制须带 NOTICE）；其余 MIT。**「吸纳」不是复制粘贴，是带许可的合并。**

## 5 三条路线

### 方案 A（推荐终态）｜内核独立，面在 DSH

- **账本**：本仓 board 内核抽成 `kernel/`（Python 包），继续「每项目一个 `board/`」；事件溯源 + 租约 + 证据分级 + 人闸 + 审计不动。
- **面**：写一个 DSH 插件（五列看板 + 卡详情 + 评审/人闸 + SSE），**通过内核的本地 HTTP API 读写**（`/api/state`、`/api/cards`、`/api/card`、`/api/run` 已存在）。taskboard **不 fork**，只当交互规格与功能对照。
- **团队**：BBFF 保留角色目录/记忆/Scope/Superpowers；`role → seat` 映射进内核，权限仍在 BBFF 的工具层。
- **守望**：sentinel-dock 当唯一常驻宿主，托管 board server、orchestrator 循环、waypost 哨兵；一份审计、一个托盘；ProcGuardTray 退役（先并跑一周）。
- **跨机**：waypost 降为「远程执行臂」——信 = 一条 `source=peer` 的任务（标记不可信），裁决 = 提交证据，状态板 = 账本镜像。
- **仓库**：本仓升为 umbrella（`contracts/` + `adapters/` + `docs/`），其余四仓**先不动**；需要单版本发布时再谈 monorepo。
- 代价：要写 DSH 面板（可先 iframe 复用现有看板页，1 天出可用版）；两套 UI 并存一段时间。

### 方案 B｜taskboard 为骨（最快，锁 DSH）

- 启用 taskboard 当唯一 UI/调度/执行宿主，**fork 它**，把 board 的 evidence/lease/audit/retry 注入；board 退为无头 CLI 兼容层。
- 好处：立刻有成熟 UI/SSE/cron/worktree/DoD/diff，开发量最小。
- 代价：跟随 0.10.x 上游 + Apache-2.0 fork 维护；DSH 停则全停；board 现有 20 道闸与测试要重接；「脱离 DSH 也能跑」这条能力丢失。

### 方案 C｜联邦（只当过渡，不当终态）

- 不动各自内核，做「统一控制台」读四份状态 + 统一 ID 映射 + 事件转发。
- 好处：一周内「看得见」。
- 代价：四份真相并存，违反「状态即证据」；写侧一律不能打通，否则必撞车。**只建议用作 P0 的只读总览。**

> **建议**：终态选 **A**，P0 用 **C 的读侧**做总览，**不选 B**（但把 taskboard 的功能清单当验收对照表）。

## 6 分阶段与闸门（拍板后开工）

| 阶段 | 做什么 | 验收闸（必须有非零反空跑） |
|---|---|---|
| **P0 契约**（1–2 天） | `TaskEnvelope v1`：id/project/goal/deliverable/acceptance/evidence/assignee/state/attempts/source；`Event v1`：append-only + `prev_hash`；四方映射表 | 故意塞一张缺证据/跨项目的坏卡 ⇒ 必须被拒；同一 key 重放 ⇒ 幂等跳过 |
| **P1 内核服务化**（1–2 周） | board 内核抽包；`board serve` 带 token；导入/导出幂等；taskboard JSON → board **dry-run** 迁移 | 迁移 dry-run 与实际导入条数对账；坏记录必须报错不静默 |
| **P2 面**（2–3 周） | DSH 插件五列 + 详情 + 评审/人闸 + SSE；先 iframe 版兜底 | 面板写操作必须落到 journal（回读事件）；没有 token 的写请求必须 403 |
| **P3 守望**（1 周） | dock 托管 board server/orchestrator/waypost；一个托盘；退役 ProcGuardTray（dry-run 并行一周） | 杀掉被托管进程能被 dock 拉起并留痕；误杀数必须为 0（对照：正常进程不受影响） |
| **P4 跨机**（1–2 周） | waypost 信 → `source=peer` 任务；结果回信；状态板镜像 | 不可信输入不得获得写权（红队样例）；重复信必须去重 |
