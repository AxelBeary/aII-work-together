## D-001 · 项目形态与一期范围（**已拍板** 2026-10-19）

| 1 | **形态** | **A 为主、B 为底**：文件即卡＝唯一事实源 ＋ 一个薄接口 ＋ 上面套本地 Web 看板；界面与引擎解耦 | 一致 |

### 依据（2026-10-19 首轮调研后补）

来源：`docs/research/20261019-agent-board-survey/98_合并摘要__发牌席__人话版.md`

1. **形态建议有据**：17 个开源产品中判 `可用` 者 **0 个**；缺的正是「跨引擎统一认领／心跳回收／完成＝证据／人的审批位不可越」四条，与 `AGENTS.md` §4 三条红线重合。⇒ 差异化不在 UI，在状态机 ⇒ 支持「B 为底、A 为面」。
2. **接入建议有据**：P2 判定所有现成协议（A2A／MCP／ACP／AG-UI／Temporal／Yjs…）**都不覆盖任务真相层**；且四个本机引擎的**退出码全部不能当成功判据**（P3）⇒ 完成判据必须自造，适配层必须可插拔。
3. **范围建议有据**：最接近我们的 KittyClaw 是 **AGPL-3.0**（改造后对外提供网络服务须开源全部改动），且仅 27 stars、新项目 ⇒ 不宜直接改造它；而 Symphony（**Apache-2.0**，规格级可抄：claim 防重复／并发上限／重试回收／状态对账）是最佳借鉴对象 ⇒ 自造薄层 + 抄规格，比改造现成产品更快到闭环。
4. **治理强度建议有据**：本项目尚无代码、无回归库；全局规则要求「首个施工批次开工前建最小回归库（≥10 条）」——先轻量起步、开工时再补回归库，符合「治理体重上限」。
5. **一条硬约束已明确**：未经用户当场同意不得在真实桌面产生可见物 ⇒ 一期**默认浏览器 Web 页**，⛔ 不做托盘／弹框／桌面通知。

- 影响面：目录结构、技术选型、派工路数、一期里程碑。
- 状态：**已拍板**（2026-10-19）

## D-007 · 多项目 + 并行 + 易用性（**已拍板** 2026-10-19）

- 日期：2026-10-19
- 指令：用户「代码库可以逐渐规整了。开一堆 worktree 出去加速做完。吸纳所有值得吸纳的 让产品简单易用 目标是单人的最佳 agent 编排看板。可以多找找网上现成轮子 吸纳。需要支持多项目。」
- 结论：

| 议题 | 裁定 | 理由 |
|---|---|---|
| **多项目存储** | **数据跟项目走**：每个项目根目录一个 `board/`；全局注册表 `~/.allworktogether/projects.json` **只记位置** | 可 git、可搬、可单独备份；删注册表不伤数据 |
| **项目识别** | **零配置**：向上找 `board/cards`（像 git 找 `.git`）；任意目录直接 `board add` 自动建并登记 | 省掉「先 init」这一步 |
| **默认值** | **项目级默认引擎/模型/思考强度**，建卡自动继承 | 最大摩擦是每次手打模型名 |
| **并行** | **每卡一个 git worktree**，`--parallel N`，建议 ≤2 | 多 agent 改同一仓库会互踩；worktree 是干净解法 |
| **冲突** | 收工只拷该卡交付物；路径重叠且内容不同 ⇒ **BLOCKED** | 守住「一个路径一个写者」 |
| **代码规整** | 拆出 `render.py`／`projects.py`／`parallel.py`；`board.py` 仍是 CLI 入口 | 渐进式，不一次性大重构（风险高） |
| **易用性** | 裸 `board` 给面板不给报错；`add` 取代 `new`；`open` 一条命令看板 | 单人工具要少记命令 |

- **未采纳（明确记录）**：一次性把 `board.py` 拆成完整包——风险大于收益，改为按职责渐进拆，每次拆完跑回归。
- 影响面：`tools/` 全部；`AGENTS.md` §2／§3.1；`README`／`docs/usage.md`
- 状态：**已拍板**

## D-004 · 架构期四条待拍板项（**已定** 2026-10-19）

- 日期：2026-10-19
- 依据：用户原话「按照最好最优，人类最轻松，整理废话最少效率最高的方式去用」⇒ 授权发牌席直接裁定，不再逐条请示。

| # | 议题 | **裁定** | 理由 |
|---|---|---|---|
| 1 | **红线②怎么强制**（D1 C-01） | **写权收归看板进程**：agent 只走 `board.py`，人走 `human`＋token；手改 `journal.jsonl` 由 `audit` 检测 | 不违背「文件即卡」；一期只接一个引擎。⛔ 不接受「只检测」——那会让红线②变成口号 |
| 2 | 卡＝目录还是单文件 | **目录**（`card.json` 契约 ＋ `journal.jsonl` 唯一真相 ＋ `lease/`／`artifacts/`／`evidence/`） | 单文件下「历史不可改写」只能靠事后校验 |
| 3 | 是否用 OS 作业对象绑进程树（C-02） | **不用** | 一期不加深平台绑定；**但文档必须写明**「租约挡不住已发生的外部副作用」 |
| 4 | 哪些卡默认强制过人闸 | **只有「不可逆动作」类**（`--irreversible` ⇒ 建议 `before_done`） | 人带宽有限（单轮 3-4 条）；全量人闸会把人变瓶颈 |

- 落地证据：`tools/board.py`（2026-10-19 闭环实测；四条防线**均有拒绝路径实测**，含反向测试）
- 影响面：`tools/board.py` 全部实现；`AGENTS.md` §4／§4.1 已同步
- 状态：**已定**
