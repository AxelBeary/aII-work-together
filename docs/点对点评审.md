# 点对点评审（B 初稿 → B1/B2 提意见 → B 自己改）

> 一句话：**评审席只准看、不准改；写权永远属于卡主。**

适用场景：翻译、写作、改文案——凡是「多一双眼睛就能变好」的活。
不适用：需要多人同时改同一份文件的活（那会串味，走卡片切段）。

---

## 为什么不是「聊天室」

| | 聊天室 | 点对点评审（本功能） |
|---|---|---|
| 什么时候结束 | 没有终点，会一直聊下去烧钱 | 一次评审有明确输入输出，结束就是结束 |
| 谁有权改文件 | 谁都能改 → 术语串味、互相覆盖 | **只有卡主能改**，评审席动了文件会被恢复并记违规 |
| 事后能不能查 | 聊完就散 | 每条意见落成卡片事件 + 磁盘证据 |

---

## 怎么用

### 一、在编排器里自动跑（推荐）

```bash
orch run --max 3 --consult "b1:opencode:claudecodesale/claude-opus-5-5,b2:qoderclicn:"
```

流程会自动变成：

```
B 初翻 → B1/B2 独立评审（并行）→ 若有 needs-work，B 按意见再改一轮 → 提交 → 复核
```

### 二、单独评审一次（手动）

```bash
board consult <卡号> --by "b1:opencode:claudecodesale/claude-opus-5-5" --role native --q "这版英译读起来自然吗"
```

### 评审席怎么写

```
seat[:engine[:model[:effort]]]
```

| 写法 | 意思 |
|---|---|
| `b1` | 用 opencode 默认模型 |
| `b1:qoderclicn:` | 换引擎 |
| `b1:opencode:claudecodesale/claude-opus-5-5` | 同引擎、换提供商 |
| `b1:opencode:model:high` | 再指定思考强度 |

多个用逗号隔开。**模型名里可以有 `/`，不会被切坏。**

### 评审角度（`--role`）

| 值 | 挑什么毛病 |
|---|---|
| `generic` | 通用（默认） |
| `native` | 母语读感（有没有翻译腔） |
| `term` | 术语与语域是否前后一致 |
| `faithful` | 逐句对照（漏译 / 增译 / 时态人称 / 数字） |

---

## 安全约束（核心，别改掉）

评审开始前给每个交付文件拍**字节快照**；结束后逐字节比对。

> 只要有一个文件被改动 ⇒ **立刻按原字节恢复** + 记 `consult_violation` 事件 + 这次评审作废。

理由：评审席拿的是完整文件内容，模型完全可能「顺手帮你改了」。没有这道闸，"只准看"就只是口头约定。

---

## 留痕

| 落点 | 内容 |
|---|---|
| 卡片事件 `consult_request` | 问题、评审席、文件哈希 |
| 卡片事件 `consult_reply` | 每席：结论、意见条数、耗时、回执哈希 |
| `board/evidence/<卡号>/consult-<时间>-<席>.md` | 该席的完整原文 |
| 卡片事件 `consult_violation` | 谁动了哪个文件（已恢复） |

`board show <卡号>` 里能看到这些事件；`board audit` 会检查有没有绕过痕迹。

---

## 两条实测经验

1. **异构评审确实有增益**：同一段译文，opus 和 deepseek 各抓到的问题不同，但**硬伤会重合**（重合的那几条一定要改）。
2. **别指望它替你判断质量**：评审席也会漏，也会给出"不改也行"的模糊建议。它的价值是**把盲点摆出来**，取舍还是人（或卡主）做。

---

## 已知问题

- 反空跑闸要求「交付物里必须包含数字」，译文的天然答案是**把统计注释写进正文**（`<!-- 3 source lines… -->`），两席评审都点出这是污染。
  目前的绕法是评审时明确要求删掉；根治要改闸门口径（改闸门前需先留档旧件，见全局规则 17）。

## 2026-10-20 补强（工程侧，不是翻译调优）

### 1. 评审席也记账了

以前只记 B 和修改轮的 token，评审席花的钱看不见。现在每席一条 `usage` 事件（`phase: consult` / `consult-verify`），成本表能看到全部四个环节。

### 2. 改完必须回头验（`consult_verify`）

原来「按意见改了一轮」是执行席的自证——正是本项目最反对的假绿。现在修改轮之后会自动再拉同一批评审席，逐条核对：

```
FIXED 1
NOT-FIXED 2
UNFIXED 1
```

结果落成 `consult_verify` 事件 + `verify-*.md` 证据，日志里给「合计未改」。

**关键口径**：评审席没按格式回 ⇒ 记为 **未知**，⛔ 绝不当成 0（测试 C7 钉住这条）。

### 3. 评审席可以带自己的角度

```
--consult "b1:opencode:claudecodesale/claude-opus-5-5@native,b2:opencode:opencode-go/deepseek-v4.1-flash@faithful"
```

`@native` 看母语读感，`@faithful` 逐句对照。没有 `@` 就用 `--role` 的统一值。

### 4. 卡片自定义字段不再被静默丢弃

实测 bug：卡上写 `consult_files: ["src/xxx.md"]`，存库时这个字段**直接消失**，程序照常跑，只是评审席永远看不到源文（评审席自己都报告「材料里没有原文」）。

修法：`cards` 表加 `meta` 列（老库自动 `ALTER TABLE` 补列），所有不在固定列里的字段进 `meta`，读出来时摊回顶层（真实列优先）。测试 C9 钉住，并做过反向测试（停用后 C9 变红）。

### 5. 用 `consult_files` 给评审席补材料

```python
"deliverables": ["en/ch01.md"],
"consult_files": ["src/ch01.md"],   # 只给评审席看，不计入交付物
```

源文也会被纳入防改快照——评审席同样不能改源文。
