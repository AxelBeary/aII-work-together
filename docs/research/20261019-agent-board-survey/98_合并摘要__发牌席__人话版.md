## 一句话结论

**「让 agent 在板上干活」已经有人做得很好了；「让所有 agent（不只写代码的）在一块板上可追责地分工」还没有人做成产品。**
我们不必从零造轮子，但**核心那一块必须自己造**——而巧的是，那一块正好就是我们 `AGENTS.md` §4 已经写下的三条红线。

## 二、已经被人解决掉的部分（可以直接站上去）

| 层 | 谁解决了 | 我们该怎么做 |
|---|---|---|
| **启动一个 agent 进程** | `codex exec`／`opencode run`／`claude -p` 全都有成熟无头形态（P2 已核官方文档） | **别造 agent 运行时**。写薄适配器即可 |
| **项目级上下文注入** | `AGENTS.md` 已是事实约定（P2 判 `可用`） | 派工时把路径与指令交给进程，别自造格式 |

| **看板 UI 与数据模型** | Plane／WeKan／OpenProject 成熟 | 借 UI 范式；但都太重（Plane 是 AGPL＋完整服务栈） |
| **调度状态机** | **OpenAI Symphony 的 SPEC.md**：claim 防重复、并发上限、重试回收、状态对账、结构化日志 | **这是本批最有价值的单件**——Apache-2.0，规格可读，可照着实现 |
| **失败模式清单** | **MAST 论文**（150 轨迹 → 14 类失效，3 大类：系统设计／agent 间错位／任务验证） | **拿它当反向设计依据**：我们的红线要有对应的失效类 |

## 三、没人解决的那一块（＝我们的机会）

P1 的 17 个产品里，**判 `可用` 的是 0 个**。缺的东西高度一致：

1. **跨引擎统一认领**：没有一家做到「任意 agent 引擎来抢同一张卡，且保证只有一个人拿到」。
2. **心跳与超时回收**：Vibe Kanban／KittyClaw／OpenHands 都只管「跑起来」，不管「跑的人失联了怎么办」。
3. **完成＝证据，不是自报**：所有产品都靠 agent 自己说完成，或靠人看 diff。**没有一家把「状态变更必须挂盘上凭据」做进状态机。**
4. **人的审批位不可被 agent 越过**：KittyClaw 有 Review 列，但那是流程约定，不是**权限不变量**。

> **这四条，正好是我们 `AGENTS.md` §4 写的三条专属红线**（状态即证据／人的拍板位不可越／认领即租约）。
> 也就是说：**我们的产品差异化，已经在治理文档里写完了**——现在要把它变成代码，而不是另想一个卖点。

## 四、必须自己造的部分（P2 结论）

P2 逐条把「它解决哪一层」写清了，结论是：**所有现成协议都不覆盖「任务真相层」**。

- A2A＝远端 agent↔agent；MCP＝agent↔工具；ACP／AG-UI＝编辑器／前端交互；Temporal／Restate／DBOS＝长流程恢复；Yjs／Automerge＝多副本合并。
- **没有一个同时解决**：卡片真相、唯一认领、证据绑定、人的审批边界。
- Yjs／Automerge 被判 **`不可用`（作任务状态权威源）**——CRDT 自动合并**恰好会破坏**「单卡单执行者」这个不变量。这是个很有用的负面结论。

**P2 还给了复议阈值**（不是规范，是本席建议，需我们拍板）：
- 上 A2A：需 ≥2 个异厂商**远端** agent 且需互相发现委派。
- 上 MCP 工具面：≥3 种 agent 客户端要复用同一套看板工具，且各写适配的成本 > 一个 MCP server。
- 上 Temporal/Restate：连续两迭代出现**可复现的进程崩溃丢进度**，且自建恢复成本 > 引入服务。
- 上 OTel tracing：跨 ≥3 台机器或 ≥3 个服务边界，或每月 ≥5 次无法靠日志重建因果链的事故。

> 这套阈值的价值：**把「不采纳」从立场变成了可判据**。以后不是「我们不上 tracing」，而是「没到那个阈值所以不上」。

## 五、本机的硬约束（会直接砸在设计上的）

P3 抽出 17 条，其中**三条会直接决定架构**：

1. **四个引擎的退出码全都不能当成功判据**（Hermes 运行错也 RC=0；qoderclicn `subtype` 会谎报；opencode 成功/失败同码）。
   ⇒ **看板的「完成」判据必须自己造**，不能透传退出码。这从工程上再次证明第三节的结论。
2. **用户是产品主、不看代码**（P3 约束 13）。
   ⇒ 验收视图必须给「截图＋人话清单＋门禁数字＋待拍板选项」；**一次最多 3-4 个决策项**。
3. **未经同意不得在真实桌面产生可见物**（P3 约束 11）。
   ⇒ 看板一期**默认必须是浏览器里打开的 Web 页**，⛔ 不做托盘／弹框／桌面通知。

## 六、许可红线（选型时必须先过这一关）

| 许可 | 项目 | 影响 |
|---|---|---|
| **AGPL-3.0** | **KittyClaw**（最接近我们的那个）、Plane、Vikunja、Focalboard | 改造后若对外提供网络服务须开源全部改动。**自用无碍，但要清楚边界** |
| GPL-3.0 | OpenProject | 同上，且更重 |
| MIT + Commons Clause | Taskmaster | **不是纯 MIT**：限制把它本身当托管服务卖 |
| Apache-2.0 | **Symphony**、Vibe Kanban、AG2、ChatDev、MetaGPT | 最宽松，**Symphony 因此是最佳借鉴对象** |
| 已停维护 | Focalboard（明写 not maintained）、Huly 旧仓（frozen）、AutoGen（archived） | ⛔ 不作新底座 |
