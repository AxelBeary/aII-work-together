# 实验设计：外问升级该由什么触发（预注册）

- 日期：2026-10-21
- 状态：**预注册，尚未跑**
- 来源：外部研究综合（`桌面\研究存档\…外问升级管线…md`）＋ 本项目实测经验
- 一句话：**验证「结构触发」是否优于「自评触发」，且级联是否真的比「直接用强模型」划算。**
- ⛔ 本文件里所有数字，除标注「实测」外，都是**估算**，不得当结论引用。

---

## 1 研究问题

| 编号 | 问题 | 为什么值得问 |
|---|---|---|
| **RQ1** | 用「可数的失败事实」触发升级，是否比「模型自评没把握」触发更准？ | 外部证据说自评置信与准确性脱钩（谄媚式元认知）；但**没有任务级对照**。 |
| **RQ2** | 两级级联（弱→强）相比「一开始就用强模型」，在**同质量**下是否更便宜？ | 多数级联研究报告只跟「弱模型单干」比，赢是必然的；真正的对手是「强模型单干」。 |
| **RQ3** | 同族复核（同一模型、不同会话）会放行多少错误？ | 盲集继承的形式化结论说「同族自检不产生增益」；本项目把「异会话复核」当红线，必须自己量一次。 |

---

## 2 假设（先写死，事后不许改）

- **H1（触发）**：结构触发的**升级精确率** ≥ 自评触发 + 15 个百分点。
- **H2（成本）**：在成功率不低于「强模型单干 − 3pp」的前提下，级联的**单题成本** ≤ 强模型单干的 60%。
- **H3（复核）**：同族复核对**错误答案**的放行率 ≥ 15%（即「复核通过」里至少六分之一是错的）。

三条都可以被数据否掉——**H1 被否就默认保留自评触发**；**H2 被否就默认「强模型单干」**；**H3 被否说明本项目的复核红线比外部结论更硬，需要在文档里注明差异**。

---

## 3 五条臂（同题、同判据、同环境）

| 臂 | 做什么 | 触发信号 |
|---|---|---|
| **W** | 弱模型单干，一次调用 | 无 |
| **G** | 强模型单干，一次调用 | 无 |
| **M** | 弱模型 → 自评触发升级到强模型 | 模型自报置信度 < 70（固定格式 `CONF: n`），低于阈值才升级 |
| **S** | 弱模型 → 结构触发升级到强模型 | 命中任一：① 机器闸红（L1/L2/L3 任一不过）② 同题连续 2 次复核 FAIL ③ 交付物缺失/零字节 ④ 重试耗尽 ⑤ 预算触顶 |
| **V** | 弱模型 + **自检一轮**，永不升级 | 无（用来把「验证的成本」与「升级的收益」拆开） |

**S 臂直接用本项目现有机制**：`--escalate-model` ＋ `--escalate-after 2`（见 D-023），不另写管线。
**M 臂**需要在提示末尾加一行「最后输出 `CONF: 0-100`」，由 runner 解析；⛔ 不许用「模型说错了」当信号。
**V 臂**是 2026-10-21 调研后补的（学界把「验证器」与「级联」分开评）：它自检一次但绝不升级，
若它在某些题上「自检后由对变错」，就证明自检本身有负收益。

**升级归因三态**（防「升级了但说不出有没有用」）：
`escalated_true`（升级后由错变对）／`escalated_waste_unneeded`（本来就对，白升级）／
`escalated_ineffective`（升级了还是错）。**误升级率 = 白升 / 全部触发**。

## 4 任务集与判真值（这是整个实验的命门）

**60 道题，三类各 20 道**，全部自建（不用公开基准，避免训练泄漏）：

| 类 | 例子 | 判真值方式 |
|---|---|---|
| **事实类** | 「给出 X 的官方文档里 Y 的默认值」 | 精确串匹配（大小写/空白归一） |
| **组合类** | 「写一个函数满足这 8 条约束」 | **隐藏单测**（题目自带 `hidden_check.py`，agent 看不到） |
| **高爆炸半径类** | 「跨 3 个文件重命名符号，保持引用一致」 | 隐藏检查脚本：跑一遍 `import`／断言零残留 |

**纪律**：
- 判真值只用隐藏检查器，**不用 LLM 当裁判**（否则就是在测第二个模型的盲集）。
- 每道题的检查器必须先在**已知正确解**上跑绿、在**已知错误解**上跑红（两把尺，否则是死判据）。
- agent 只能看到题面与交付物路径，看不到检查器。

## 5 仪器：现在有什么、要补什么

**已有（本项目看板现成）**：`events` 里的 `claim/submit/verify/review/usage/engine_error/escalate`；
`usage` 里有 token 与 cost；`duration_ms`；L1/L2/L3 读数；租约与重试次数。

**要补两个字段（各一行）**：
1. 每次运行的 `trigger`：`none | metacognitive | structural`（写进 `usage` 或单独事件）；
2. 每题每臂的 `arm` 标签（写进卡号前缀即可，如 `W-01`、`S-01`）。

> 这样成本、时长、往返次数、失败原因全部可直接从库里聚合，不用二次埋点。

---

## 6 指标

| 指标 | 定义 | 主次 |
|---|---|---|
| **成功率** | 隐藏检查器判 pass 的比例 | 主（RQ1/RQ2） |
| **单题成本** | 该题所有引擎调用的 cost 之和（含升级与复核） | 主（RQ2） |
| **升级精确率** | 升级后由 fail→pass 的题 / 所有升级的题 | 主（RQ1） |
| **误升级率** | 升级前其实已经对的题 / 所有升级的题 | 主（RQ1） |
| **复核放行率** | 复核 pass 的题里隐藏检查器判 fail 的比例 | 主（RQ3） |
| **往返次数** | 每题的引擎调用次数 | 次 |
| **时延** | 每题墙钟时长（p50/p90） | 次 |

## 7 统计与样本量

- 配对设计（同题跨臂），主检验用 **McNemar**（W vs S、G vs S），成本用 **bootstrap 10k 次** 置信区间。
- **60 题**：假设不一致对 ~30%，可检出约 **25pp** 的成功率差异（80% power，α=0.05）——**这是估算，不是保证**。
- 要检出 15pp 需要约 **140 题**（估算）。第一轮先跑 60 题当 **pilot**，看效应量再决定是否扩到 140。
- **难度校准闸（2026-10-21 pilot 后补）**：正式跑之前必须先只跑 W 臂，**弱模型通过率必须 ≤60%**；
  否则题库没有区分度，H1/H2/H3 全部无法检验（pilot 实测：10 题弱模型 100% 通过，四臂全部 0 触发）。
- **改法（2026-10-21 调研后定）**：**不是「造更难的题」，而是「筛题」**——先跑 W，只保留历史通过率
  落在 **30–70%** 带的题（区间外两端都无信息量：70–100% 太易、0–30% 二者都不会，也区分不出）。
  依据：Efficient Benchmarking of AI Agents（arXiv:2603.23749）在 8 基准/33 scaffold/70+ 配置上验证，
  题量减 44–70% 而排名保真度不降；>95% 正确率视为无信息量（IRT 综述 arXiv:2607.15190）。
  ⚠️ 15 题全对的单侧 95% 置信下界约 82%（Clopper–Pearson），**不足以宣称「已饱和」**——pilot 只能说「无区分度」。
- 成本预算（估算）：单题单臂 ~$0.006（本项目 2026-10-21 实测区间 $0.0035–$0.0066）⇒ 4 臂 × 60 题 ≈ **$1.5**；加复核与返工，按 **$10 上限** 报预算。

## 8 预注册的弃用条件（跑完必须照此裁决）

| 观察 | 裁决 |
|---|---|
| S 的成功率 ≤ G − 5pp，且 S 成本 ≥ 0.8×G | **放弃级联**，默认「强模型单干」 |
| S 的误升级率 > 40% | 触发太松：先收紧触发器（去掉 ①②中较弱的一支），不换结论 |
| M 的升级精确率 ≥ S − 5pp | **H1 被否**：自评触发并不差，应重新审视外部结论的适用边界 |
| 复核放行率 < 15% | **H3 被否**：本项目「异会话复核」可能确实提供了增益，需在文档里注明与外部结论的差异 |

## 9 已知威胁与外推限制

1. **单机、单模型族**：结论只对这两个模型族与这台机器成立；换供应商要重跑。
2. **题目自建**：不代表公开基准，**不可外推为「模型能力」结论**；只能支持「在这类任务上触发策略更优」。
3. **判真值由本项目写**：检查器本身可能有 bug——所以 §4 要求两把尺（已知对/已知错都要验）。
4. **价格会变**：成本结论必须带日期与模型版本号，30 天后作废。
5. **S 臂的触发阈值（2 次）是我们自己定的**：它既是实验变量也是产品默认值，结论只能用来说明「这个默认值合不合适」，不能反过来证明结构触发一定更好。

## 10 执行步骤（一个人四天可跑完）

| 天 | 做什么 | 完成判据 |
|---|---|---|
| D1 | 写 60 道题 ＋ 60 个 `hidden_check.py`；对每题跑一遍「已知正确解」与「已知错误解」 | 60/60 检查器双向验证通过 |
| D2 | runner：读题 → 建卡（带 `--escalate-model`）→ 跑 → 记 `arm` 与 `trigger` → 汇总成 CSV | 4 臂各跑通 2 题冒烟 |
| D3 | 全量跑 4 臂 | 240 次运行全部落库，失败也有记录 |
| D4 | 分析：McNemar / bootstrap / 成本前沿图；对照 §8 裁决 | 一份带数字的结论表（含「不确定」项） |

> 复用现有闸门：实验本身也走 `board submit → verify → review`，**不允许绕开**——否则实验测的是「绕过闸门的能力」，不是触发策略。

## 11 结果怎么落回产品

- H1/H2 成立 ⇒ `--escalate-after` 默认值保留 2；在 `board add` 帮助里写清「返工 2 次换强模型」。
- H2 不成立 ⇒ README 明确写「**优先直接用强模型**，级联只在预算受限时用」。
- H3 成立 ⇒ 把「复核通过」在界面与文档里统一标为 `AUDITED-UNGROUNDED`（已在 D-023 落地），并禁止在任何对外材料里写「已验证」。

---

## 附：本设计刻意没做的事

- 不做多 Agent 辩论（外部证据已否定同质辩论，且我们要测的是触发，不是共识机制）。
- 不让模型自评分作为**唯一**信号以外的判据混入 S 臂（否则两组不可比）。
- 不追求统计显著性本身：60 题是 pilot，目的是**看效应量与成本量级**，不是发论文。
