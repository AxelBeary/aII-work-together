## 0 先决条件（不满足就别开跑）

```powershell
python "docs\research\20261021-escalation-experiment\exp\run_experiment.py" --validate
# 期望：23 of 23 通过；单条件变异体 0 条未被抓住
```
**检查器不自证就不许跑模型**——错解也能过闸的话，整轮数据作废。

自检现在有三层（缺一层都可能假绿）：

| 层 | 抓什么 | 抓不到什么 |
|---|---|---|
| 两把尺（ok/bad） | 检查器对「整份烂答案」有没有区分力 | 作者自己写错的期望（ok/bad 同一个人写，错得自洽） |
| 第三把尺（`ORACLES`） | 手写期望 vs 独立实现算出的期望 | 只有可计算的题能上（当前 N01/N04） |
| 单条件变异（`variants.py`） | 检查器里**每一条独立条件**是否真的生效 | 只覆盖登记过的变异点（当前 6 题 6 条） |

## 1 筛题（只跑弱模型，按 30–70% 通过率带留题）

```powershell
python "docs\research\20261021-escalation-experiment\exp\screen.py" --repeat 3 --timeout 300
```

- 每题跑 3 次：`3/3` = 太易、`0/3` = 太难、`1/3`~`2/3` = **留**。
- 结果落 `exp/runs/screen-*.json`，表尾直接给 keep 列表。
- ⚠️ **单次通过率不是概率**：3 次只是粗筛；真正进实验的题建议 ≥5 次复测后再定。

## 2 五臂

```powershell
python "docs\research\20261021-escalation-experiment\exp\run_experiment.py" `
  --arms W,G,M,S,V --tasks <筛后题号> --timeout 300
```

| 臂 | 是什么 | 用来看什么 |
|---|---|---|
| **W** | 弱模型单干 | 基线（对照） |
| **G** | 强模型单干 | 上限与成本上界 |
| **M** | 弱 →（自评 `CONF<70`）→ 强 | 自评信号可不可用 |
| **S** | 弱 →（检查器判红）→ 强 | 结构信号（我们产品里的做法） |
| **V** | 弱 + 自检一轮，**不升级** | 把「验证成本」和「升级收益」拆开 |

## 3 分析

```powershell
python "docs\research\20261021-escalation-experiment\exp\analyze.py"
```

输出四块：
1. 每臂 n／通过率／升级次数／花费／墙钟中位；
2. **触发器质量**：真收益 / 白升（本来就对）/ 升了也没用 ⇒ **误升级率**；
3. **V 臂**：自检修好几题、**自检改坏几题**（后者比前者重要）；
4. `conf` 缺失条数（缺失＝无效样本，⛔ 不算升级理由）。

## 4 判读规则（事先定好，防止事后找理由）

| 现象 | 结论 | 动作 |
|---|---|---|
| `S` 的通过率 ≈ `G`，且花费 ≪ `G` | 结构触发有效 | 保持 `--escalate-after` 现状 |
| `S` 通过率明显低于 `G` | 触发太晚/检查器看不见那类错 | 换触发器或加自检 |
| `M` 误升级率 > 50% | 自评不可用（pilot 已见 100% 那次是 bug，修后还需复测） | 不把自评当默认触发器 |
| `V` 自检改坏 > 0 | 自检有害 | 自检必须配「只准改不许删」或干脆取消 |
| 全臂通过率都 >90% | 题库仍饱和 | 换难度轴，**不要加题量** |
| 全臂通过率都 <10% | 题库太难，同样无信息 | 降难度 |

## 5 纪律

- 每轮结果落 `exp/runs/*.jsonl`（append-only），⛔ 不覆盖旧文件。
- 报告里每个数字必须能指到某个 jsonl 行；引用旧数据要带日期。
- ⛔ 对外材料不得用 pilot 数字支持「级联更好/更差」。
- 跑闸门前清环境：`Remove-Item Env:ABOARD_REGISTRY_DIR`、`ABOARD_SEAT`。
